# 駭客入侵（BREACH）— 資安卡牌遊戲

扮演駭客，入侵一間企業完成任務；玩完之後，你就知道怎麼防。
規則來源：`資安桌游.md`（單人遊戲版）。

## 怎麼玩

- 雙擊 **`啟動遊戲.bat`**，瀏覽器會自動開啟遊戲（第一次會花一點時間準備）。
- 企業情境（傳統工廠、新創公司、醫院、學校）與任務每局都是隨機抽的；開場看完劇本，按「開始」亮出起手牌。
- 任務都是真實的駭客目標：**勒索大作戰**（加密資料勒索）、**竊取資料**、**癱瘓服務**、**假老闆詐騙**、**內鬼資料外洩**。
- 每局開場拿滿 **8 張手牌**。有任務終結牌的任務會把指定卡固定放進這 8 張起手牌；換牌不能丟掉它，打出後若未獲勝，下一次抽牌一定優先抽回。
- 每個瀏覽器分頁都是獨立的一局（進度、前後測成績、承諾都只存在該分頁），多開不會互相干擾。
- 把手牌**拖到目標身上**或**拖到場上**出牌；拖到右下角的棄牌堆可以花 1 點換牌。直接控制牌也能用在已控制的目標：成功後，剩餘控制時間再加上該節點完整的控制時長；仍須符合卡牌條件並支付費用與噪音。
- 手機開場先橫放並點擊全螢幕；瀏覽器不支援時可橫向繼續。長按卡牌可放大閱讀，移動手指即收起並接續拖曳；點按或長按節點、側欄圖示與層級鎖頭可查看詳細資訊。
- `空白鍵` 結束回合；首回合須先出牌或換牌一次，不能直接空過。結算演出中按任意處或空白鍵可加速。
- 出牌演出：牌先飛到場中央蓄力，再射向目標；成功時爆開，被防護擋下時撞碎，什麼也沒發生時燒成灰（`CastLayer.vue`）。
  賽博病毒會讓基礎設施「被感染」（髒綠光、小蟲沿著邊框爬），每回合病毒回報弱點時會有封包飛向被翻開的那一格。

## 開發

```
npm install
npm run dev        # 開發（http://127.0.0.1:5173/）
npm run build      # 打包到 dist/（使用相對路徑，可放在網站任何子路徑）
npm test           # 規則回歸：起手、任務保留、分層與多目標互動
npm run preview    # 預覽打包結果
node scripts/check-deal.ts 3000 # 大量開局檢查（起手／牌堆／路線）
node scripts/sim.ts 100    # 用電腦玩家模擬平衡（每種組合 100 局）
node scripts/gen-icons.mjs # 圖示清單有增減時重新產生 src/components/icons.ts
```

## 公司的反應：倒數

沒有「公司回合」，也沒有事件牌。公司的反應都是看得見的倒數：

- **任何方式翻開的弱點都會公開**，公司會開始倒數修復；歸零就失效。這包括偵查、入侵時用到的弱點，以及病毒回報的弱點。
- **被你控制的節點**會開始倒數，歸零就被奪回，當初入侵的弱點也一起被修補。
- 受控節點會顯示奪回時間；已揭露弱點會顯示修補時間。
- 控制節點的奪回倒數比原值延長約三分之一（無條件進位）；弱點修復與備份恢復時間不變。
- 備份是通用支援節點：控制備份且未癱瘓後，之後每回合多抽 1 張牌（手牌上限仍為 8）。備份被你控制、癱瘓或揭露「破釜沉舟」時，IT、基礎設施與資料庫的奪回倒數每回合只走一半；其他節點（含備份）不變。
- 警戒值越高，倒數走得越快（平靜 ×1、起疑 ×1.5、全面調查 ×2）。
- **癱瘓**可以暫停倒數：「警報轟炸」癱瘓 IT 管理員 2 回合，期間修復與奪回全部暫停；
  控制 IT 管理員則讓公司無法修復弱點。「破壞備份」癱瘓備份約 6 回合，並讓 IT、基礎設施與資料庫的奪回速度減半。

## 分層攻擊與出牌規則

棋盤的三層是**外圍 → 內網 → 核心**。外圍一開始就能攻擊；控制任一外圍節點後，一般攻擊可以進入內網；控制任一內網節點後，一般攻擊可以進入核心。遊戲會依每次出牌時仍然存在的控制權重新判斷路徑：若提供路徑的節點被公司奪回，該路徑就會關閉；已控制的深層節點不會因此立即失控，仍照自己的奪回倒數計算。

有些已知弱點可以提供捷徑：

- 基礎設施有「遠端大門」時，可以直接攻擊基礎設施，不必先控制外圍。
- 控制外圍節點並利用基礎設施的「自由海域」，可以越過內網攻擊核心節點。
- 控制任一員工並利用資料庫的「權限大開」，或控制 AI 助理並利用其「萬能鑰匙」，可以直接攻擊資料庫；這兩條捷徑只通往資料庫。

只有已確認可達的節點才能指定為攻擊目標；未揭露的捷徑不會解鎖目標，也不能靠盲打繞過鎖。攻擊路徑不會替你控制節點，仍要符合卡牌與目標弱點條件。偵查只會揭露當下開放層級或已控制節點的弱點：開局為外圍，控制外圍開啟內網，控制內網開啟核心；已揭露的捷徑則可打開其通往的目標。對已確認可達的節點仍可盲打弱點；成功時會揭露用到的弱點，失敗時會指出遭到防護或不存在的條件。

「橫向移動」要拖到一個已控制的節點；它會隨機控制同層或畫面下方一層的一個未控制節點：核心可擴散到核心或內網，內網可擴散到內網或外圍，外圍只能在外圍擴散。來源若沒有合適的未控制節點，就不能打出這張牌。

## 規則補充

- **換牌**：把手牌拖到棄牌堆，花 1 點行動點換一張。任務終結牌不能用這個方式丟棄；打出後若未獲勝，下次透過回合補牌、抽牌效果或換牌抽牌時，一定優先抽回。
- **抽牌與行動點**：開局 6 張；之後每回合抽 2 張，手牌最多 8 張（滿了就不抽）。沒用完的行動點最多保留 2 點到下一回合，「囤積補給」讓這回合結束時最多保留 4 點。
- **節點能力**：一般員工每回合 +1 行動點；主管受控時，「惡意技能」「USB 間諜」「橫向移動」各少花 1 點（最低 1）。AI 每回合可免費打出一張費用 1 點的牌，包含主管折價後的擴散牌；免費額度用完後正常付費。
- **資源管理牌**（綠色「支援」牌，不算在攻擊流程裡，噪音為 0）：清除日誌（1 點，警戒 -2）、跳板代理（2 點，警戒 -3）、暗網情報（1 點，抽 2 張）、熬夜趕工（0 點，本回合行動點 +2）、囤積補給（1 點，本回合結束最多保留 4 點行動點）。
- 每局牌堆只放本局需要的「得手」牌。任務指定的得手牌一定在起手 6 張裡，不能被換牌丟掉。
- 不會發到整局都無法使用的攻擊牌：依開局配置檢查可利用的弱點與可取得的控制權前置；所有路線都不成立才排除。拿到牌只代表有可行路線，不代表此刻盲打會成功；可先取得控制權、偵查，或換牌。
- **跨目標攻擊**：密碼攻擊可選員工、IT、基礎設施、資料庫或備份；目標須有「簡單密碼」，員工也可用「一碼超人」。漏洞利用可攻擊有「爛系統」或「老古董」的員工、IT、基礎設施、資料庫或備份。遠端大門只提供攻擊基礎設施的入口，本身不會取代密碼弱點。
- **員工弱點連動**：「社交工程」利用「好騙」或「社群分享狂」控制員工；「按讚手」由「登入轟炸」利用。「尾隨入侵」利用目標員工的「好心人」放行，在基礎設施已開放時，各半機率控制基礎設施或癱瘓它 2 回合，不會控制開門的員工。癱瘓期間公司修復與奪回暫停，但不算取得基礎設施控制權。
- **開局節奏**：起手 6 張包含任務牌；缺少時從原洗好的牌堆交換出一張可用偵查牌及一張可嘗試的員工入侵牌（牌池沒有員工入侵時改選其他入侵手段）。只依公開條件選牌，不保證猜中隱藏弱點，不增加卡片數量，也不改變後續抽牌。
- **設備相關牌**：「USB 間諜」可先控制員工，或利用可接觸員工「工作習慣很差」留下的未鎖螢幕入口，打出後只會控制已開放的基礎設施；「賽博病毒」需要控制基礎設施與任一員工，基礎設施癱瘓期間暫停偵查、恢復後繼續；「警報轟炸」需要控制基礎設施與任一非 IT 員工；「破壞備份」需要控制基礎設施，並控制 IT 或資料庫。控制基礎設施後，可用「橫向移動」繼續擴散。
- **備份互動**：「破釜沉舟」會讓勒索軟體得手；控制備份也能讓勒索軟體得手。資料庫的「權限大開」仍只解鎖對資料庫出牌，必須真正控制資料庫才能完成竊取資料任務；私人雲端風險已併入「權限大開」，控制員工不會直接取得資料。竊取資料已揭露「明文存放」時只需維持 1 回合。
- **假老闆詐騙**：控制主管與基礎設施以接管公司 Teams，再對有「好騙」弱點的員工打出「假冒轉帳」。
- **套話偵查**：「能言善道」只能選員工；控制員工，或目標有「好騙／社群分享狂」，即可揭露該員工一個弱點。「按讚手」可被登入轟炸或社交工程利用；「一碼超人」可用撞庫攻擊或密碼攻擊；「社群分享狂」也會讓肉搜情報更便宜並揭露更多。
- **AI 攻擊**：「提示詞注入」可利用 AI 的「照單全收／取代人類」，或在控制 IT 後控制 AI；「惡意技能」可利用 AI 的「自我更新」，或在控制員工後控制 AI。AI 的「照單全收」與「自我更新」也會讓盟友偵查取得更多線索。
- 搜尋類的牌只會翻出弱點，不會翻出防護；翻到沒有更多弱點時，節點會標示「—」。完全沒有弱點的節點（每一格都是防護）看起來和別的節點一樣蓋著牌；硬用偵查牌去翻，其中一格會翻成「無懈可擊」。病毒等連鎖反應只會翻真正的弱點，不會浪費在這種節點上。
- 開局時，同一個弱點與它自己的防護牌不會同時出現。盲打保留尚未揭露資訊的不確定性，不會預先洩漏蓋著的弱點。
- **內鬼資料外洩**：控制一名員工與資料庫後，打出任務牌「資料外送」即可得手。
- 公司把所有可用路線都補死時，直接判定失敗（路線被封死）。

## 平衡調整

- 每回合行動點：`src/game/engine.ts` 的 `BASE_AP`
- 開局「已防護」牌的比重：`TUNING.shieldWeight`（目前 0.5；越小，開局越多可用弱點。`node scripts/stats.ts` 可看分佈）
- 抽牌與行動點：`src/game/engine.ts` 的 `OPENING_HAND`、`DRAW_PER_TURN`、`HAND_MAX`、`AP_CARRY_MAX`
- 各牌在牌堆的張數：`CARD_COPIES`
- 各企業情境的弱點分佈：`src/game/data.ts` 的 `SCENARIOS`
- 牌的費用與噪音：`src/game/data.ts`；公司修復／奪回的回合數：`VULN_RISK`、`NODE_RISK`（顯眼度、嚴重度），反應速度 `ZONE_SPEED`
