# 駭客入侵（BREACH）— 資安卡牌遊戲

扮演駭客，入侵一間企業完成任務；玩完之後，你就知道怎麼防。
規則來源：`資安桌游.md`（單人遊戲版）。

## 怎麼玩

- 雙擊 **`啟動遊戲.bat`**，瀏覽器會自動開啟遊戲（第一次會花一點時間準備）。
- 企業情境（傳統工廠、新創公司、醫院、學校）與任務每局都是隨機抽的；開場看完劇本，按「開始」才發牌。
- 任務都是真實的駭客目標：**勒索大作戰**（加密資料勒索）、**竊取資料**、**癱瘓服務**、**假老闆詐騙**、**AI 助理洩密**。
- 每個瀏覽器分頁都是獨立的一局（進度、前後測成績、承諾都只存在該分頁），多開不會互相干擾。
- 把手牌**拖到目標身上**或**拖到場上**出牌；拖到右下角的棄牌堆可以花 1 點換牌。
- `空白鍵` 結束回合；結算演出中按任意處或空白鍵可加速。
- 出牌演出：牌先飛到場中央蓄力，再射向目標；成功時爆開，被防護擋下時撞碎，什麼也沒發生時燒成灰（`CastLayer.vue`）。
  賽博病毒會讓基礎設施「被感染」（髒綠光、小蟲沿著邊框爬），每回合病毒回報弱點時會有封包飛向被翻開的那一格。

## 開發

```
npm install
npm run dev        # 開發（http://127.0.0.1:5173/）
npm run build      # 打包到 dist/（使用相對路徑，可放在網站任何子路徑）
npm run preview    # 預覽打包結果
node scripts/sim.ts 100    # 用電腦玩家模擬平衡（每種組合 100 局）
node scripts/gen-icons.mjs # 圖示清單有增減時重新產生 src/components/icons.ts
```

## 結構

```
src/game/
  types.ts     資料型別
  data.ts      弱點、手牌、事件、任務、企業情境（所有文字與數值）
  engine.ts    規則引擎（不依賴畫面，可在 Node 直接跑）
  progress.ts  任務進度（畫面顯示用）
  quiz.ts      前後測題目與紀錄
  store.ts     把規則與畫面動畫串在一起（拖曳、出牌、回合結束的倒數演出）
src/components/  畫面元件
src/audio/sfx.ts  用瀏覽器合成的音效（不需音檔）
scripts/         模擬器與圖示產生器
```

## 公司的反應：倒數

沒有「公司回合」，也沒有事件牌。公司的反應都是看得見的倒數：

- **公開的弱點**（用「自動掃瞄」翻開的）會開始倒數，歸零就被修復；隱密偵查公司不知道，不會倒數。
- **被你控制的節點**會開始倒數，歸零就被奪回，當初入侵的弱點也一起被修補。
- 每種弱點、每個節點的回合數都不同，依「顯眼程度」與「嚴重程度」決定（越顯眼、越嚴重，越快）；
  滑過節點可以看到。
- 警戒值越高，倒數走得越快（平靜 ×1、起疑 ×1.5、全面調查 ×2）。
- **癱瘓**可以暫停倒數：「警報轟炸」癱瘓 IT 管理員 2 回合，期間修復與奪回全部暫停；
  控制 IT 管理員則讓公司無法修復弱點。「破壞備份」癱瘓備份，約 6 回合後才恢復。

## 規則上補充的地方

原規則沒寫、實作時補上的決定：

- **橫向移動**（擴散，2／2）：原規則沒有「取得資料庫控制權」的牌，補一張。
  條件是「攻擊得到核心層」（控制內網任一節點，或自由海域／權限大開／萬能鑰匙的捷徑）。
- **換牌**：手牌用不到會塞滿，所以可拖到棄牌堆花 1 點行動點換一張。
- **抽牌**：開局發 5 張，之後每回合抽 2 張，手牌最多 8 張（滿了就不抽）。
- **保留行動點**：沒用完的行動點最多保留 2 點到下一回合（「囤積補給」讓這回合結束時最多保留 4 點）。
- **資源管理牌**（綠色「支援」牌，不算在攻擊流程裡，噪音都是 0）：清除日誌（1 點，警戒 -2）、跳板代理（2 點，警戒 -3）、暗網情報（1 點，抽 2 張）、熬夜趕工（0 點，本回合行動點 +2）、囤積補給（1 點，本回合結束最多保留 4 點行動點）。
- 每局牌堆只放該任務用得到的「得手」牌。
- 不會發到用不上的牌：牌需要的弱點，如果整個公司完全沒有（蓋著、翻開、被公司修好都算「有」），那張牌整局不放進牌堆（`uselessCards`）。
  開局整手都打不出去的機率約 0.03%。檢查方式：`node scripts/check-deal.ts 3000`。
- 能言善道：原文是「有員工有『好騙』就揭露指定節點的 1 個弱點」，條件看的是**任一員工**，目標是**你指定的節點**。
- 肉搜情報對已知是「社群分享狂」的員工費用 -1（還沒揭露時，打完才退還 1 點，避免洩漏）。
- 開局若隨機抽到完全無解的配置，會整副重抽。
- 搜尋類的牌只會翻出弱點，不會翻出防護；翻到沒有更多弱點時，節點會標示「—」。
- 開局時，同一個弱點與它自己的防護牌不會同時出現，所以每個弱點都一定有效。
- 盲打成功時，用到的弱點（包含走進核心層的捷徑）會一併翻開；失敗時，會看到是哪一道防護擋住了你，或確認該弱點不存在。
- 公司把所有能走的路都補死時，直接判定失敗（路線被封死）。

## 平衡調整

- 每回合行動點：`src/game/engine.ts` 的 `BASE_AP`
- 開局「已防護」牌的比重：`TUNING.shieldWeight`（目前 0.7；越小，開局越多可用弱點。`node scripts/stats.ts` 可看分佈）
- 抽牌與行動點：`src/game/engine.ts` 的 `OPENING_HAND`、`DRAW_PER_TURN`、`HAND_MAX`、`AP_CARRY_MAX`
- 各牌在牌堆的張數：`CARD_COPIES`
- 各企業情境的弱點分佈：`src/game/data.ts` 的 `SCENARIOS`
- 牌的費用與噪音：`src/game/data.ts`；公司修復／奪回的回合數：`VULN_RISK`、`NODE_RISK`（顯眼度、嚴重度），反應速度 `ZONE_SPEED`
